# БАЗА — сайт bazaone.ru

Корпоративный сайт «БАЗА — CRM и автоматизация под ваш бизнес».
Статика: чистый HTML/CSS/JS, **без фреймворков, библиотек и сборки**.

## Деплой

- Хостинг — **GitHub Pages** из ветки `main` (домен в `CNAME`, `.nojekyll` отключает Jekyll).
- Любой merge/push в `main` публикуется автоматически за ~1 минуту
  (Actions → «pages build and deployment»).
- Изменения делаются в отдельной ветке → pull request → merge.
- **Проверка перед публикацией:** в каждом pull request GitHub сам запускает
  `.github/workflows/site-check.yml`. Зелёная галочка — можно мержить; красный крестик — что-то
  сломано, причина в логе (вкладка Checks → «Проверка сайта»). Что проверяется — см. ниже.
- **Стили главной собираются в один файл** `css/site.css` (так страница грузится быстрее).
  После правки любого CSS-файла главной запустите `node tools/build-css.mjs` — он пересоберёт
  `site.css` и сам обновит `?v=` в `index.html`. Забыли — проверка в PR подскажет.
- После правки JS **поднимайте `?v=N`** в подключении скрипта в HTML — иначе браузеры
  покажут старую версию из кэша.

## Главная: блоки

Каждый блок — `<section>` в `index.html` + свой CSS-исходник (и JS, если есть анимация).
Все CSS-исходники главной собираются в `css/site.css` — список и порядок в `tools/build-css.mjs`.

| Блок | id / класс | CSS | JS |
|---|---|---|---|
| Шапка и мобильное меню | `.nav`, `.mmenu` | `menu.css` | `menu.js` |
| Hero: логотип, иконки Артем & Анна, заголовок | `.hero` | `hero.css` | `hero.js` |
| Продукт, счётчик до открытия 12.12.2026 | `#block1` | `block1.css` | `block1.js` + inline-скрипт |
| Персонализация | `#personalization` | `persn.css` | — |
| Аналитика и разведка (12 направлений, 2 страницы) | `#analytics` | `analytics.css` | inline-скрипт |
| О нас | `#block5` | `block5.css` | — |
| Контакты + форма заявки | `#block6` | `block6.css` | `lead-send.js` + `form.js` |
| Футер, cookie-баннер | `.foot`, `[data-cookie]` | `footer.css`, `cookie.css` | `cookie.js` + `metrika.js` |

**Временно скрыты** (ещё в тёмной теме, вернутся после перевода в светлую):
`#how`, `#kit`, `#result`, `#story`, `#grow`, `#faq`, `#block2`, `#block3`, `#block4` —
скрыты одной строкой в `css/light.css`. Разметка и стили остаются в репо, но их CSS
**не входит** в `site.css`, а их скрипты (`block2–4.js`) не подключены — чтобы не замедлять страницу.
Вернуть блок: убрать его id из списка в `light.css`, добавить его CSS в `SOURCES` в
`tools/build-css.mjs` (перед `light.css`), подключить скрипт, если есть, и запустить сборку.

### Тема

Исходно сайт был тёмным. `css/light.css` подключается **последним** и переводит в светлую тему
шапку, Hero и блоки, которые уже переведены. Новый блок в светлой теме = правила в `light.css`
+ удалить его id из списка скрытых.

### Общие механики

- `data-reveal` (+ `data-reveal-delay="1..n"`) — плавное появление при скролле
  (`reveal.css` / `reveal.js`).
- `prefers-reduced-motion` уважается: анимации отключаются.

## Формы заявок

Форма на главной (`js/form.js`) проверяет поля (обязательные поля, мат-капча,
согласие на обработку ПДн) и передаёт заявку в общий модуль **`js/lead-send.js`**:

1. `POST` JSON на адрес из `<meta name="form-endpoint">`; таймаут 12 с, один повтор при сбое сети / 5xx.
2. Успех — сообщение «Спасибо», форма очищается.
3. Неудача — форма **не очищается**, под ней появляется сообщение с кнопками «Написать на почту»
   (письмо на go@bazaone.ru с уже заполненным текстом) и «Скопировать заявку».
   Почтовый клиент сам не открывается.
4. Неотправленная заявка сохраняется в браузере посетителя и тихо досылается при его
   следующем заходе на сайт (с пометкой «Повторная отправка»; хранится до 14 дней).

**Адрес сервера заявок** задан в одном месте — `<meta name="form-endpoint">` в `index.html`.

Защита от спама:
- в каждой форме скрытое поле-ловушка `website` (honeypot): люди его не видят, боты заполняют;
  `lead-send.js` передаёт его на сервер только если оно не пустое;
- на сервере — `baza-guard.php` (подключается одной строкой в `send.php` и `admin.php`):
  отбрасывает заявки с заполненным `website`, лимит 5 заявок / 10 мин и 20 / сутки с одного IP,
  защита админки от перебора паролей и белый список IP.
  Бэкенд (`send.php`, `admin.php`, `baza-guard.php`) в этом репозитории **не хранится**.

## Аналитика

Яндекс Метрика, счётчик **112432279** (`js/metrika.js`, подключён на главной).

- Счётчик загружается **только после «Принять»** в cookie-баннере (`cookie.js` шлёт событие
  `baza:cookie-consent`). «Отклонить» — ни одного запроса к Яндексу. Так требует 152-ФЗ.
- Вебвизор выключен: он записывает ввод в формы, то есть персональные данные.
- Цели (в Метрике: Цели → «JavaScript-событие», идентификатор как ниже):
  `lead_sent` — заявка отправлена; `lead_failed` — сервер заявок не ответил;
  `lead_resent` — неотправленная заявка дослана при следующем заходе.
  Рост `lead_failed` = сервер заявок сломан.
- Цель из любого скрипта: `window.BAZA.goal('имя_цели')` (без согласия ничего не делает).

## SEO и превью ссылок

- `robots.txt`, `sitemap.xml` — при добавлении страницы допишите её в `sitemap.xml`.
- На каждой странице — `<link rel="canonical">` и Open Graph (`og:*`), превью в мессенджерах —
  `assets/og-image.jpg` (1200×630). Исходник картинки — `_agent_notes/og-image/og.html`
  (не публикуется): открыть через локальный сервер и снять скриншот 1200×630.
- На главной один `<h1>` (в Hero), заголовки остальных блоков — `<h2>`.

## Проверка перед публикацией

`tools/check-site.mjs` открывает сайт в настоящем браузере (десктоп и телефон) и проверяет
все страницы из `sitemap.xml` и `404.html`:

- все файлы загружаются, нет битых картинок и ошибок JavaScript;
- нет запросов на чужие серверы (Google и т. п. — 152-ФЗ);
- внутренние ссылки и якоря ведут на существующее; на странице один `<h1>`;
- Яндекс Метрика не грузится до согласия и грузится после «Принять»;
- форма заявки: успешная отправка и поведение при отказе сервера
  (запросы к `api.bazaone.ru` перехватываются — настоящие заявки не уходят).

Плюс отдельный шаг: `css/site.css` пересобран после правки исходников.

Запустить локально: `python3 -m http.server 8080 &` и
`npm i --no-save playwright && npx playwright install chromium && BASE_URL=http://127.0.0.1:8080 node tools/check-site.mjs`.

## Скорость

Lighthouse, главная (28.09.2026): телефон **87**, десктоп **100**; доступность, SEO и
практики — 100. Что держит скорость и не стоит ломать:

- стили — один файл `css/site.css` (сборка `tools/build-css.mjs`, с минификацией);
- шрифты первого экрана — `<link rel="preload">` в `<head>` `index.html`;
- иконки Hero — `srcset` с облегчёнными `*-400.png` для телефонов и `fetchpriority="high"`;
- у картинок заданы `width`/`height` (нет сдвигов вёрстки);
- cookie-баннер показывается с первой отрисовки (inline-скрипт в `<head>` + `css/cookie.css`);
- скрытые блоки не грузят ни CSS, ни JS.

Правила для картинок:
- фоны — **WebP + JPEG-фолбэк** через `image-set()` (как в `css/hero.css`, `css/menu.css`);
- размер — не больше 2× максимального показа на экране (для retina), фон ≲ 150 КБ;
- новый файл сразу подключайте в код — неиспользуемые ассеты не храним.

Шрифты — **только локальные**, запросов к Google нет (152-ФЗ: IP посетителей не уходят за рубеж):
- `css/webfonts.css` — Geist, Onest, Lora, Geist Mono, JetBrains Mono (подмножества cyrillic,
  latin, latin-ext; файлы `assets/fonts/<шрифт>-<подмножество>.woff2`);
- `css/fonts.css` — Playfair Display (`pf-*`), PT Sans (`pts-*`).

Не подключайте шрифты с `fonts.googleapis.com` — скачивайте woff2 в `assets/fonts/`.
