# Правила для AI-агентов в репозитории bazaone.ru

Единые правила для всех агентов (Claude Code, Codex, Cursor, Copilot и др.).
Файл `CLAUDE.md` подключает этот файл — правьте правила только здесь.

Этот репозиторий — **только маркетинговый сайт bazaone.ru** (статичный HTML/CSS/JS на GitHub Pages).
Подробное устройство сайта — в `README.md`: прочитайте его перед любыми правками.

## Границы: что здесь НЕ живёт и что трогать нельзя

| Система | Где живёт | Правило для агента в этом репо |
|---|---|---|
| **app.bazaone.ru** — SaaS БАЗА (проектируется) | отдельный репозиторий и сервер | Не создавать здесь код, страницы, конфиги или папки для app. Не добавлять поддомены в `CNAME`. Ссылки на app с сайта — только обычные `<a href="https://app.bazaone.ru/…">`, по прямой просьбе. |
| **api.bazaone.ru** — приём заявок (`send.php`) и временная админка (`admin.php`) | отдельный сервер, кода в репо нет | Не менять `<meta name="form-endpoint">` в `index.html` и `admin/index.html` без прямой просьбы. Не писать здесь серверный код. |
| **DNS домена bazaone.ru** | у регистратора | Не менять `CNAME`, не предлагать правки DNS как часть задачи по сайту. |
| **Яндекс Метрика 112432279** | `js/metrika.js` | Не менять ID, не включать Вебвизор, не загружать счётчик до согласия на cookie (152-ФЗ). |

Если задача требует изменений вне сайта — **остановитесь и спросите**, не делайте «заодно».

## Как вносить изменения

`main` защищён правилом GitHub: прямой push и force-push в `main` **невозможны** — ни агенту, ни человеку.
Любой коммит в `main` сразу публикуется на живой сайт, поэтому путь только один:

1. Создайте ветку от свежего `main` и работайте в ней.
2. Перед пушем прогоните проверку локально:
   ```bash
   node tools/build-css.mjs                      # если меняли CSS главной
   python3 -m http.server 8080 &
   BASE_URL=http://127.0.0.1:8080 node tools/check-site.mjs
   ```
3. Запушьте ветку и откройте pull request в `main`.
4. В PR запустится «Проверка сайта» (`.github/workflows/site-check.yml`). Смержить PR можно только
   при зелёной проверке. Красная — чините в той же ветке, не просите мержить и не обходите проверку.
5. Решите, кто мержит: **автомерж** или **человек** — по правилам ниже.

Если push в `main` отклонён (`push declined due to repository rule violations`) — это ожидаемо:
перенесите коммиты в ветку и откройте PR. Не пытайтесь обойти правило.

## Автомерж или решение человека

Автомерж = PR сам вливается в `main`, когда «Проверка сайта» зелёная. Включает его агент, открывший PR.

### Автомерж разрешён, только если выполнены ВСЕ условия

- Правка **техническая**: оптимизация, исправление бага, стили без заметного изменения дизайна,
  сжатие картинок, удаление неиспользуемых ассетов, правки `tools/`, `README.md`.
- Текст на сайте меняется максимум на уровне **опечаток и пунктуации** — смысл не меняется.
- Не затронут ни один пункт из списка «Только человек».
- Локальная проверка прошла.

### Только человек (автомерж НЕ включать), если PR затрагивает хоть что-то из этого

- **Тексты и смысл:** заголовки, офферы, описания услуг, цены, кейсы, контакты, реквизиты, имена.
- **Юридические страницы:** `privacy.html`, `consent.html`, `cookie.html`, тексты согласий и cookie-баннера.
- **Структура:** добавление, удаление, скрытие или возврат блоков и страниц; меню; переходы
  (`admin/`, `forum/`); `sitemap.xml`, `robots.txt`, `CNAME`, `404.html`.
- **Дизайн:** заметные изменения цветов, шрифтов, сетки, анимаций, картинок первого экрана.
- **Формы и данные (152-ФЗ):** `js/lead-send.js`, `js/form.js`, `js/cookie.js`, `js/metrika.js`,
  `<meta name="form-endpoint">`, поле-ловушка `website`.
- **Правила и автоматизация:** `CLAUDE.md`, `AGENTS.md`, `.github/`, `tools/check-site.mjs`
  (ослабление проверки — всегда через человека).
- Удаление файлов, кроме неиспользуемых ассетов.
- **Сомневаетесь — значит, человек.**

### Как оформить PR

- Заголовок и описание — по-русски: что изменено и зачем, как проверено.
- Последняя строка описания — решение и причина, например:
  `Автомерж: да — сжатие картинок, внешний вид не меняется` или
  `Автомерж: нет — меняется текст оффера, нужно решение человека`.
- Включить автомерж (способ слияния — merge commit):
  - Claude Code: инструмент GitHub `enable_pr_auto_merge` (merge method `MERGE`);
  - Codex / терминал: `gh pr merge <номер> --auto --merge`.
- Если автомерж не включается (выключен в настройках репозитория) — оставьте PR человеку
  и напишите об этом в ответе пользователю.
- Для PR «только человек» — сообщите пользователю ссылку на PR и что именно нужно проверить.

## Обязательные соглашения

- **CSS главной** правится в исходниках `css/*.css`, затем `node tools/build-css.mjs`.
  `css/site.css` — сгенерированный файл, руками не редактировать.
- **JS:** после правки поднимайте `?v=N` в подключении скрипта в HTML.
- **Внешние ресурсы запрещены:** никаких Google Fonts, CDN, сторонних скриптов и пикселей —
  всё хранится в репо (152-ФЗ; проверка в PR упадёт). Исключение — Яндекс Метрика по согласию.
- **Картинки:** WebP + JPEG-фолбэк для фонов, не больше 2× размера показа; неиспользуемые ассеты не храним.
- **Один `<h1>`** на странице; у картинок `width`/`height`.
- **Формы** отправляют заявки только через `js/lead-send.js`; поле-ловушку `website` не удалять.
- Скрытые блоки (`#how`, `#kit`, … — список в `css/light.css`) не удалять: они ждут перевода в светлую тему.
- `admin/index.html` и `forum/index.html` — страницы-переходы, нужны; не удалять.
- После изменений, которые меняют устройство сайта, обновляйте `README.md`.

## Секреты и данные

- В репо **не бывает** паролей, токенов, ключей API, адресов почтовых ящиков для входа, данных клиентов.
  Репозиторий и сайт публичны.
- Заявки из форм — персональные данные. Не логировать их содержимое, не отправлять
  на сторонние сервисы, не сохранять в репо даже в тестах (в `tools/check-site.mjs`
  запросы к `api.bazaone.ru` перехватываются — так и должно остаться).
